## 1. 结论

当前核心功能运行稳定，完整行为检查仍通过，但不是“没有可优化项”。建议在正式发布前至少处理两类问题：

1. **6 张携带帧底部外描边触及画布最后一行，存在 1 行裁切。**这是本轮全帧扩展审计新发现的实际素材缺陷，既有坐姿/携带像素探针没有覆盖“不得触碰画布边缘”这一条件。
2. **Electron 与打包工具链需要单独升级评估。**官方 npm audit 报告 19 项公告（1 critical、15 high、3 moderate）；数量不等于本应用均存在可直接利用路径，但当前依赖不宜不经评估就继续作为下一次正式发布基线。

其余主要是气泡视觉细节、设置反馈、自然动作可发现性、动画过渡和工程维护优化，不影响本轮 34 项行为检查通过的事实。

## 3. 建议优先修复

### P1-A：携带帧底部外描边裁切

- `carry_0@1x.png` 至 `carry_5@1x.png` 的最后一行均存在 5–6 个深黑外描边像素。
- 当前轮廓连通组件检查为 1，只能证明轮廓没有分裂，**不能证明轮廓没有被画布裁断**。
- 建议调整携带姿态的垂直安全区，保证四边至少保留 1 个原生像素的透明边距；保持 76×68 栅格、统一调色板及拖拽锚点不变。
- 修复后新增全帧边界守卫，并重跑携带像素审计、真实拖拽、携带姿态、窗口同步、原生命中及完整矩阵。

- 当前安装树为 Electron 33.4.11、electron-builder 25.1.8。

## 4. 用户体验优化

### P2-A：让气泡尾部始终指向猫咪，并正确显示时段

当前有两处独立细节：

- 气泡靠近屏幕上边时会改放到猫咪下方，但尾部仍固定在底部；猫咪靠近左右边缘时，尾部也仍固定在 50%，可能没有指向猫咪。
- `KIND_LABEL[payload.kind] ?? PERIOD_LABEL[payload.period]` 会优先显示“时段”，使清晨/午后/傍晚/夜晚标签被覆盖。

建议主进程把 `placement`、`tailX` 一并交给气泡页面：上方气泡用下尾，下方气泡用上尾，尾部水平位置跟随猫咪中心并限制在安全区间；`kind === 'time'` 时优先显示时段标签。补充顶部、左右边缘和多显示器工作区专项。

### P2-B：设置“已保存”应以真实结果为准

- 设置页在 IPC 更新后立即显示“设置已应用并保存”。
- 实际配置写入有 400ms 防抖，写入失败目前只记录日志；开机自启异常也只记录日志。
- 因此磁盘权限、写入失败或系统自启未生效时，界面仍可能给出成功暗示。

建议设置页区分“已应用”和“已保存”：设置变更等待主进程 flush 并返回成功/失败；失败时保留可见错误，不回滚当前内存状态。自启设置可读取系统实际状态后再确认。增加写入失败与自启失败负例，不能只测正常路径。

### P2-C：增加自然动作预览和频率控制

这是最能改善“功能已经做了，但用户看不到”的优化：

- 在行为页增加“预览动作”下拉框及播放按钮，可立即查看七种动作。
- 增加随机自然动作开关和频率档位，默认仍保持当前低频，避免改变既有打扰程度。
- 预览必须沿用正式 `Animator`，遵循拖拽、暂停、隐藏、锁屏和其他覆盖动作的互斥规则，不能另建一套动画播放路径。
- 该属于新交互能力，实施前应单独确认，不在本轮审查中直接加入。

## 5. 动画与工程优化

### P3-A：减少部分动作的入场/退场跳变

全帧测量中，较大的单帧重心变化包括：

- `roll_0 → roll_1`：约 8.96 个原生像素；
- `groom_0 → groom_1`：约 8.87 个原生像素；
- `groom_6 → groom_7`：约 8.40 个原生像素；
- `wakeUp_6 → wakeUp_7`：约 7.78 个原生像素。

在 3× 显示下，约 9 个原生像素相当于一帧移动约 27 个屏幕像素，可能产生“摆姿势跳切”。建议保持用户已选款式不变，只在入场和退场增加 1–2 张过渡帧，并重新做白底与真实窗口复核。无需为优化而改动全部动作。

### P3-B：拆分测试探针与生产代码

- `src/main/main.ts` 约 2766 行，约 900–2682 行大量承担 smoke/probe 逻辑；`renderer.ts` 约 1382 行，也包含测试钩子。
- 建议把主进程探针、窗口管理和设置/气泡 IPC 分模块，测试代码仅在测试模式加载；保留现有环境变量和脚本协议，避免一次重写测试体系。
- 这主要是降低修改风险和审查成本，不应宣称会直接带来明显性能提升。

### P3-C：小型清理与耗电优化

- `settingsScanTimer` 每 2 秒运行一次，即使设置窗口从未打开也存在；可改为设置窗口打开时启动、关闭时清理，插件页不在前台时减少同步目录扫描。
- `art/sprites/chibi-hd/walk_strip.png` 未被当前 `meta.json` 引用，且不会进入运行目录；可确认无手工用途后再清理，不能混入功能修复直接删除。
- 83 张原生 PNG 合计约 114 KB，解码后的原始 RGBA 约 1.72 MB，当前没有为了省内存而重写图集懒加载的必要。

## 6. 安全与既有能力中表现良好的部分

- 三个渲染页面均有严格 CSP；禁用 Node integration，启用 context isolation 和 sandbox。
- 新窗口打开被拒绝，设置与桌宠页面限制导航；外部仓库地址固定，插件目录只列目录和打开文件夹，不执行外部插件代码。
- 配置通过统一校验，损坏配置有备份恢复与隔离保存；测试使用独立 userData 和只读配置，不污染正式配置。
- 测试钩子只在测试模式安装，正常启动不开放驱动拖拽和修改配置的全局测试 API。
- 绘制脏键、遮罩复用、60/30Hz 调度、暂停停循环、隐藏/锁屏停止和渲染恢复均通过本轮回归。

## 7. 仍需人工硬件验收

自动测试没有替代以下真实环境：

- 双屏热插拔、显示器位置变化和固定显示器移除；
- 100%/125%/150% 混合 DPI 下跨屏拖动、气泡跟随与原生命中；
- 真实拔电/接电、Windows 锁屏、休眠和唤醒；
- 开机自启在真实安装版与便携版中的系统结果；
- 新依赖版本下的安装、卸载、便携目录退出清理和 Windows SmartScreen 表现。

## 8. 推荐实施顺序

1. **小范围修正**：携带帧安全边距 + 全帧边界守卫。
2. **逐项体验修正**：气泡尾部/时段 → 保存与自启反馈；每项独立验证。
3. **经确认后增加**：自然动作预览和频率设置。
4. **单独依赖维护**：升级 Electron / electron-builder，重跑完整矩阵和真实打包验收。
5. **可选视觉精修**：只为跳变明显的动作补过渡帧。

以上步骤都不需要改变用户已经选定的动作风格，也不要求立即打包。

- 气泡尾部方向、边缘水平指向和具体时段标签已实现，并通过顶部与左边缘真实窗口专项。
- 设置保存等待真实 flush，自启读取实际状态；正常路径与两类失败负例均通过，测试不会修改真实 Windows 启动项。
- 自然动作新增随机开关、三档频率与七键预览；预览复用正式 Animator，并验证关闭随机、暂停和隐藏场景。
- 保留原 83 张关键帧，新增 20 张过渡帧，当前为 14 组 103 帧。最大重心跳变从 8.96 降为 4.25 原生像素；原生与六倍源图保留检查为 83/83。
- 设置探针已拆分，矩阵逐项增量落盘，旧 `walk_strip.png` 已清理。审查中提到的 `settingsScanTimer` 在当前源码复核中并不存在，实际只有配置更新时的状态同步与目录扫描，因此没有按这段过期描述做虚假删除或声称耗电优化。
